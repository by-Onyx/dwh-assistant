# Лабораторная 02 — LangChain и память фактов

[← Оглавление](../../README.md)

**[Notebook с кодом и выполненной демонстрацией](notebooks/02_fact_memory.ipynb).** DWH-ассистент запоминает имя, стек, уровень, цели и сведения о проекте. В долгосрочной памяти — отдельные факты, а не переписка. Служебные события отображаются в собственной CELL, основной чат содержит сообщения пользователя и ответы.

## Запуск

Установите пакет и зависимости по [корневому README](../../README.md). Команды выполняются из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m ipykernel install --prefix .venv --name dwh-assistant --display-name "Python (DWH assistant)"
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_notebook.ps1
```

Можно открыть файл напрямую:

```powershell
.\.venv\Scripts\python.exe -m notebook labs/02_fact_memory/notebooks/02_fact_memory.ipynb
```

Выберите ядро **Python (DWH assistant)**. Последовательно выполните импорты, служебную CELL, конфигурацию и чат. Пакет устанавливается через `pip install -e .`, поэтому Notebook работает и при рабочей папке `notebooks/`, без ручной правки `sys.path`.

В конфигурации: `BACKEND = "local-4b"`, свой `USER_ID`, `MEMORY_PATH = MEMORY_FILE`. Рабочая память по умолчанию — `var/memory.json`. Модели/сервер — `var/models/` и `var/runtime/`. Чтобы использовать прежнюю папку с моделями, задайте `DWH_ASSETS_DIR` перед запуском Jupyter либо параметр `-AssetsDir` у `scripts/start_notebook.ps1`. Для CPU задайте `CPU = True`. Для готового внешнего локального сервера — `START_LOCAL_SERVER = False`.

## Проверка после перезапуска

1. Сообщите: «Меня зовут Алексей. Мой стек — Python и PostgreSQL. Мой уровень — начинающий аналитик. Моя цель — спроектировать DWH для автосалона. Предметная область — автосалон».
2. Проверьте `memory_saved` в служебной CELL. Команда `/memory` показывает текущие факты там же.
3. Отправьте `/exit`, перезапустите ядро и снова выполните ячейки запуска с прежним `USER_ID`.
4. Спросите: «Как меня зовут, какой у меня стек и какая цель? Затем задай следующий вопрос анкеты».

`/forget stack` удаляет одно поле, `/clear` — только текущий профиль, `/exit` закрывает чат с сохранением памяти. Для исправления сообщите полное новое значение поля. Идентификатор профиля разделяет данные, но не является механизмом аутентификации.

## Буфер, сводка и уровень знаний

В пределах одного сеанса агент держит последние `WINDOW_TURNS` завершённых пар «вопрос — ответ» (по умолчанию 2, допустимо 1–8). При переполнении отдельная цепочка LangChain объединяет самую старую пару с прежней сводкой. Следующий ответ получает обновлённую сводку и реплики из окна с исходными ролями. Длинные реплики сокращаются с сохранением начала и конца, сводка ограничена 1000 символами. После перезапуска остаётся профиль в JSON.

Команда `/remember <поле> <значение>` вызывает [компонент записи](../../src/dwh_agent/memory_command.py). Например, `/remember level начинающий аналитик` сохраняет всё значение после имени поля. Компонент проверяет имя и значение по схеме фактов и записывает результат в файл текущего пользователя. Результат записи виден в служебной ячейке. Свободный текст по-прежнему обрабатывает LLM-извлекатель.

Уровень из профиля задаёт сложность ответа и вопроса для самопроверки. Для новичка агент объясняет термин на одном примере, для среднего уровня предлагает прикладную задачу, для эксперта — выбор между проектными решениями. Команда `/practice` выбирает готовый вопрос о зерне фактов по той же ветке. При неизвестном уровне используется общий режим. Поле `teaching_mode` в событии `answer_ready` показывает выбранную ветку.

В Notebook выполните ячейку **«Буфер, сводка и сложность вопроса»**. Она вызывает команду `/practice` до и после смены уровня, показывает сводку и продолжает разговор. В чате команда `/memory` выводит профиль, сводку и число пар в окне. Команды `/forget <поле>` и `/clear` сбрасывают также оперативный контекст этого чата, поскольку он может содержать удаляемые сведения.

## Реализация и ограничения

Извлекатель получает только текущее сообщение. Ответ использует профиль, сводку и последние реплики. [Хранилище фактов](../../src/dwh_agent/fact_memory.py) проверяет JSON и подтверждающие цитаты, защищает файл блокировкой и заменяет его атомарно. [Буфер и сводка](../../src/dwh_agent/dialogue_memory.py) принадлежат конкретному экземпляру агента.

Модель может пропустить факт, потерять деталь при сжатии или ошибиться в ответе по DWH. Поля стека и целей хранятся строками; новое полное значение заменяет предыдущее. Проверки механизма памяти и ветвления находятся в [тестах диалога](../../tests/test_dialogue_memory.py).
