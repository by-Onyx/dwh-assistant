# Пример DWH для сети аптек

## Запрос и допущения примера

50 аптек; ежедневная загрузка; чеки с позициями и возвратами; одна позиция может использовать несколько партий; распределение количества известно. Остатки по аптеке, препарату, партии и дню. Есть поступления, перемещения, списания. Срок годности — атрибут партии. Валюта единая, количества в базовой единице. Приоритет: продажи, остатки, списания. Дефицит — по доступности; потерянные продажи не измеряются. Эти сведения — учебные допущения, не описание реальной организации.

## Пример после ручной корректировки

Следующий проект исправлен автором решения после просмотра ответа модели. Он **не является сырым ответом 4B**. Все названия таблиц/полей — проектные предложения.

| Факт | Одна строка | Числовые меры |
|---|---|---|
| fact_sale_line | источник + чек + номер позиции | количество; сумма продажи по согласованной учетной политике |
| fact_sale_batch_allocation | позиция продажи + партия (повторные распределения агрегированы) | распределенное количество |
| fact_inventory_daily | аптека + препарат + партия + дата снимка | остаток в базовой единице |
| fact_inventory_movement | источник + документ движения + позиция + партия/строка распределения | количество по типу операции; исходная/целевая локация |
| fact_return_line | источник + документ возврата + позиция | количество и сумма возврата; ссылка на исходную продажу, если доступна |

Поступления, списания и перемещения — типы событий в факте движений. Если источники и grain существенно различаются, их выделяют в отдельные факты. Перемещение имеет исходную и целевую аптеку; в балансе каждой локации учитывается соответствующее направление. Возвраты не следует повторно учитывать и в отдельном факте, и как дополнительный поток движений без правила сверки.

Общие измерения: дата, аптека, препарат, партия, тип операции/причина списания; поставщик — для процессов, где связь существует. У партии хранится expiry_date; snapshot_date находится в факте остатков. Валюта — код/измерение, сумма — числовая мера. При одной валюте код может быть константой.

В позиции продажи нет единственной партии. Связь с партиями — через allocation; сумма распределенных количеств равна количеству позиции. Денежные суммы нельзя дублировать по партиям: для денежной аналитики по партии требуется явное правило распределения и сверка сумм.

Каждый факт связывается с общими измерениями. Для совместной аналитики факты сначала агрегируют к сопоставимому grain, например аптека × препарат × день; прямой JOIN сырых позиций и снимков по препарату размножает строки.

Показатели:

- Продажи в количестве — сумма количества позиций за период. Net sales требует правил возвратов, отмен, скидок и дат отражения.
- Остаток — сумма по выбранной дате снимка, не сумма по дням. Средний запас — среднее дневных суммарных остатков при полном календаре снимков.
- Просроченный запас — остаток партий с expiry_date < дата оценки; включение последнего дня годности уточняется. Риск истечения за N дней — отдельный KPI с согласованным N.
- Доступность — наличие пригодного к продаже запаса по аптеке и препарату. Доля дней отсутствия считается по полному набору «активный ассортимент × аптека × день», а не только по ненулевым строкам остатков. Резервы, карантин, статус партии и ассортимент необходимо определить. Это индикатор доступности, а не потерянные продажи.
- Покрытие в днях = пригодный запас / средний дневной спрос при ненулевом знаменателе. Источник спроса и окно оценки не заданы; продажи не объявляются автоматически полным спросом.

Сверка: конец = начало + поступления + возвращенное на склад + входящие перемещения − продажи − списания − исходящие перемещения + корректировки. Все величины в сопоставимых единицах и с согласованным моментом отсечения. Нужно исключить двойной учет возвратов и перемещений.

Загрузка: raw/staging → согласованные измерения и факты → витрины. Уникальные исходные ключи и водяные знаки/идемпотентный upsert; ежедневная загрузка с согласованной задержкой. История SCD2 — для нужных изменяемых атрибутов аптеки/препарата; факты связываются с версией на дату события. Для сроков годности следует согласовать обработку исправлений источника.

Проверки: уникальность grain, ссылки на измерения, полнота дат/ключей, распределение по партиям, сверка запасов, направления перемещений, пропуски снимков, отсутствие пересечений SCD2. Отрицательные значения проверяются по типу операции и учетной политике; универсальный запрет некорректен.

Уточнить: учетная политика сумм/возвратов; пригодный запас и активный ассортимент; причины списания; граница expiry_date; поздние исправления и SLA.

**Предварительный дизайн DWH для сети аптек**

**Предположения:**  
- Все продажи и возвраты привязаны к позиции чека и партии.  
- Остатки хранятся по аптеке, препарату, партии и дате снимка.  
- Списания по сроку годности — только при нарушении (expiry_date < assessment_date).  
- Один чек-строк может быть распределён между несколькими партиями (распределение по количеству).  
- Валюта — единая, количество — в базовой единице.  
- Дефицит — по доступности (остатки < спрос), не измеряется как потеря продаж.  

---

**Факты и гранулярность:**  
| Факт | Гранулярность | Измерения |  
|------|---------------|----------|  
| `fact_sales` | receipt_id + line_no + batch_id | продажа_количества, продажа_суммы |  
| `fact_stock_snapshot` | location_id + product_id + batch_id + snapshot_date | остаток_количества |  
| `fact_writeoff` | batch_id + location_id + writeoff_date | объём_списания |  
| `fact_transfer` | from_location_id + to_location_id + batch_id + transfer_date | объём_перемещения |  

---

**Связи (конформированные измерения):**  
- `fact_sales` → `dim_product` (product_id), `dim_batch` (batch_id), `dim_location` (location_id), `dim_receipt` (receipt_id, line_no)  
- `fact_stock_snapshot` → `dim_product`, `dim_batch`, `dim_location`, `dim_date` (snapshot_date)  
- `fact_writeoff` → `dim_batch`, `dim_location`  
- `fact_transfer` → `dim_location`, `dim_batch`  

---

**Ключевые показатели (KPI):**  
1. **Продажи по партии** = сумма продаж по batch_id  
2. **Остатки по дате** = остаток_количества в snapshot  
3. **Списания по сроку годности** = объём списания, где expiry_date < snapshot_date  
4. **Дефицит (по доступности)** = спрос (продажи) > остатки (на дату)  

---

**Учёт партий и сроков годности:**  
- Каждая партия имеет `expiry_date`.  
- Списание происходит только при `expiry_date < snapshot_date` (на момент снимка).  
- Распределение продаж по партиям — через `fact_sales` с `batch_id`.  

---

**Качество и проверки:**  
- Проверка: сумма продаж по партии = сумме распределённых количеств.  
- Проверка: остатки в snapshot должны соответствовать балансу (поступления – продажи – списания – перемещения).  
- Проверка: `expiry_date` не может быть в прошлом на момент снимка (для партий, не участвующих в продажах).  
- История изменений — SCD2 для `dim_product`, `dim_batch`, `dim_location` (с датой изменения).  

**Примечание:** Валюта не является измерением, количество — единица измерения.
