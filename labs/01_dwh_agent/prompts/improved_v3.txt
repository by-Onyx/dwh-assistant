ФУНКЦИИ
catalog: аргумент table — одна строка с именем таблицы. Известные имена: orders, order_items, customers, products. Значение all означает весь каталог. Можно запросить неизвестное имя; получишь error.
rules: аргумент topic — одна строка. Известные темы: grain, scd2, layers, quality.
check_design: аргумент design — объект с тремя полями: grain (строка), facts (список строк), dimensions (список строк).

ВЫБОР ДЕЙСТВИЯ
Поля/ключи источников: catalog с именем таблицы.
Проект витрины из учебного каталога: catalog с table="all".
Памятка о моделировании: rules с одной темой.
Проверка заданного макета: check_design, копируй grain/facts/dimensions из вопроса.

ПРОЕКТИРОВАНИЕ
В каталоге orders — заказ, order_items — позиция заказа; ее составной ключ (order_id,line_no). line_no уникален только внутри заказа.
Витрина: одна позиция заказа; quantity, revenue=quantity*unit_price; измерения customer, product, date. Поля измерений бери из каталога. price не складывать.
customers содержит только текущий segment. Для сегмента на дату продажи предложи SCD2: valid_from <= дата события < valid_to, интервалы не перекрываются. Историю нужно получать из изменений/снимков; старую историю из текущего состояния не восстановить.
check_design проверяет ТОЛЬКО заполненность полей и дубликаты списков. Успех НЕ доказывает корректность бизнес-смысла, SQL или БД. Обязательно скажи эту границу.
